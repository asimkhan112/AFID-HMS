Defects Resolved

5 items · all verified against the live API
FIX-01

Password hashing crashed — login, registration & seeding all broken

Critical Resolved
Area
Authentication — auth.py
Symptom
Every password operation raised ValueError / AttributeError. No user could log in or be created, and the DB seed script failed.
Root cause
The pinned passlib 1.7.4 (unmaintained since 2020) is incompatible with the installed bcrypt 5.0 — it reads a __about__ attribute that no longer exists.
Fix
Replaced passlib with the bcrypt library directly (with the required 72-byte truncation) and updated requirements.txt.
Verified
Correct password → JWT issued; wrong password → 401; all three roles authenticate.
FIX-02

HOD monitoring dashboard returned a server error

High Resolved
Endpoint
GET /hod/monitoring
Symptom
HTTP 500 on every call — the HOD "Doctor Monitoring" view never loaded.
Root cause
The response schema DoctorMonitoringOut requires total_active_cases, but the router never supplied it → Pydantic validation error.
Fix
Compute each doctor's ACTIVE-patient count and include it in the response (routers/hod.py).
Verified
Endpoint now returns 200 with a populated row per doctor.
FIX-03

Approving or rejecting a leave request crashed every time

High Resolved
Endpoint
PATCH /leaves/{id}/status
Symptom
HTTP 500 whenever an HOD clicked Approve/Reject — leave status silently stayed PENDING.
Root cause
The handler read payload.reviewed_by, but the LeaveStatusUpdate schema had no such field → AttributeError.
Fix
Added the optional reviewed_by field to the schema (falls back to the reviewing HOD's name).
Verified
Approve now returns 200; status → APPROVED with reviewed_by recorded.
FIX-04

Patient timeline steps could not be created

High Resolved
Endpoint
POST /hod/timeline/{mr}/steps
Symptom
HTTP 422 on every request — no timeline step could be added; HOD/reception timelines always showed zero.
Root cause
The create schema required patient_id in the request body, but the router derives it from the URL's MR number — the field was both mandatory and unusable.
Fix
Pointed the create schema at the base model so patient_id is no longer expected in the body (schemas.py).
Verified
Step creation returns 201 and steps read back correctly; HOD timeline test now passes.
FIX-05

A wrong-password login reloaded the page instead of showing an error

Medium Resolved
Area
Frontend — api.js
Symptom
Entering a wrong password bounced the user through a "Session expired" reload rather than showing "Incorrect email or password".
Root cause
The shared fetch helper treated any 401 as an expired session — including a 401 from the login call itself — and force-redirected to the login page.
Fix
Excluded /auth/login from the global 401-redirect so the backend's real error surfaces on the form.
Verified
Invalid-credential tests now pass; token-expiry redirect behaviour on other pages unchanged.

Database & Environment

A key question for this bring-up was whether the app was genuinely on PostgreSQL or still on SQLite/JSON. Findings and actions:

  • Code layer is fully on PostgreSQL. The engine has no SQLite fallback; psycopg2 is the driver; there are no .db, .sqlite, or JSON data files anywhere in the repo.
  • The app had no .env and pointed at a database (afid_db) that did not exist; the only DB present (afid_hms_db) was a stale, unrelated schema from an earlier stack. Created the .env, provisioned a clean afid_db (owner afid_user), and seeded it.
  • Result: 18 tables created and seeded — 8 users, 7 patients, doctor profiles, staff, operatory rooms, timeline steps, and 6 procedure presets. Backend, frontend and database all run cleanly.

Remaining Test Failures — Not Application Defects

9 items · reviewed individually

The nine still-red tests were each traced to their cause and confirmed not to be application bugs. They break down as:

Test-side timing races — the UI fires its confirmation alert() after an async save, but the test asserts on it synchronously; the underlying flows (leave submission, session completion) were confirmed working via the API.

Stale test assumptions — e.g. one test asserts the leave form should have no "leave type" selector, but the app correctly offers one; another expects a check-in timestamp at registration, whereas the app records it when the patient becomes active.

Shared-fixture isolation — a few tests assume a specific doctor's queue is empty while other tests in the same run assign patients to that same doctor.

Deliberate design / security — the reception portal cannot mark a session "complete" (the doctor does), and receptionists are correctly denied the HOD timeline endpoint — a restriction the security test suite itself asserts is required.

Recommendation: tidy these on the test side (await the dialog, isolate fixtures) rather than change working product behaviour.
